# Career Quest

AI-навигатор развития сотрудника. Хакатон-демо на Streamlit с синтетическими профилями, личным кабинетом, HR-аналитикой и сохраняемым прогрессом.

## Запуск одной командой

Нужен Python 3.11+ с модулем venv. Из корня проекта:

```powershell
python run.py
# Если Windows знает только launcher Python:
py -3 run.py
```

При первом запуске создаётся отдельное `.venv-career` и устанавливаются зависимости (нужен интернет). Следующие запуски используют это окружение. Открыть http://localhost:8501. SQLite создаётся автоматически; MySQL для MVP не требуется.

Если зависимости уже установлены: `python -m streamlit run app.py`. Для ручной установки: `python -m pip install -r requirement.txt`. В VS Code выберите интерпретатор `.venv-career/Scripts/python.exe` (Windows), чтобы Pylance видел зависимости, включая dotenv.

## Демо-вход

| Роль | Логин | Пароль |
| --- | --- | --- |
| Сотрудник | employee1, employee2 или employee3 | Quest2026! |
| HR | hr | HrQuest2026! |

Роль выбирается на экране входа, но права проверяются по учётной записи в БД. Сотрудник видит только себя; HR открывает любой профиль, аналитику и импорт. Сессия действует 8 часов, выход отзывает токен. После пяти неудачных попыток вход блокируется на минуту. Пароли хранятся как PBKDF2-хеши с индивидуальной солью.

Публичные демо-доступы предназначены только для вымышленных данных. Это не корпоративная система авторизации: перед реальным внедрением требуются SSO/OIDC, HTTPS, управление пользователями и отключение демо-аккаунтов. Приложение по умолчанию слушает только 127.0.0.1.

## Проверка на защите

1. Войдите как employee1. Public Speaking — минимальный навык, но после трёх пропусков и с критичным System Design первым предлагается архитектурное менторство. В каждой рекомендации четыре фактора и формула приоритета.
2. Нажмите «Начать», затем «Отметить выполненной». System Design изменится с 50 до 65, готовность к грейду вырастет, начислится 180 XP при выполнении в срок. Повторное начисление запрещено.
3. employee2 получает базовый SQL-практикум: продвинутый SQL исключён из-за невыполненных предпосылок.
4. Для employee3 пока нет подходящей активности. HR видит эту ситуацию и причину, вместо выдуманной рекомендации.
5. Войдите как HR: обзор дефицитов, участников активностей, профили и история. Во вкладке «Загрузка датасета» скачайте пример и импортируйте его. Появятся ещё три проверочных профиля и индивидуальные доступы к ним.
6. Войдите по выданным доступам и выполните шаг. HR увидит обновление после «Обновить данные». Перезапуск сервера не сбрасывает прогресс.

## Датасеты жюри

Формат — UTF-8 JSON, до 2 МБ. [Готовый пример](data/jury-example.json). JSON Schema скачивается из HR-кабинета; модели находятся в `services/dataset.py`.

- Верхний уровень: `schema_version: 1`, `synthetic: true`, `employees`, `activities`, `history`.
- Профиль: `id`, вымышленное `name`, `role` (должность, НЕ право доступа), `grade`, `next_grade`, `tenure_months` (12–60), `skills` (0–100), `requirements` (target 1–100, weight 1–5, critical), `preferred_formats`, `opted_in`.
- Активность: `id`, `title`, `format`, допустимые текущие `grades`, приросты `gains`, `prerequisites`, `minutes`, `xp`, `due_days`, `voluntary`.
- История: `employee_id`, `activity_id`, `status` (completed, missed, declined, started), `date` (YYYY-MM-DD); необязательные `due_date`, `xp`.
- Навыки — текущий снимок ПОСЛЕ импортированной истории. История не начисляет прирост повторно. Без явного `xp` исторические записи дают 0 XP.
- ID уникальны; неизвестные поля, неверные типы/диапазоны/даты и ссылки отклоняются. Для пары сотрудник/активность допустимо одно текущее started/completed, пропуски можно повторять.
- Датасет самодостаточный: включает каталог для всех ссылок истории. Импорт добавляет новые профили; одинаковую существующую активность можно переиспользовать. Конфликт ID профиля или разное содержимое активности отклоняют весь импорт.
- Лимит хранилища: 200 профилей, 200 активностей, 5000 событий при импорте. Все записи и учётные записи добавляются одной транзакцией.
- HR получает случайные пароли новых сотрудников только в текущей сессии и может скачать их. Датасет не может создать HR-учётную запись.

## Рекомендации и OpenAI

Локальный режим явно подписан «Многофакторный подбор · без AI». Сначала отбираются добровольные активности по текущему грейду и предпосылкам, исключаются начатые, выполненные и отклонённые. Затем приоритет получают критичные разрывы следующего грейда. Внутри группы учитываются взвешенный прирост, предпочитаемый формат, успешная история и пропуски похожих активностей. Выдаётся до трёх шагов; если подходящих нет — причина.

Для настоящего AI-подбора скопируйте `env.example` в `.env`, задайте `OPENAI_API_KEY` и `ALLOW_EXTERNAL_AI=true`. В сотрудническом кабинете подтвердите отправку синтетических данных и нажмите «Получить AI-рекомендации». Модель выбирает 1–3 ID из подходящего каталога; сервер проверяет допустимость, уникальность и приоритет критичных требований. Обоснования строятся из проверенных фактов профиля. При ошибке/таймауте включается явно обозначенный локальный режим.

Используется [OpenAI Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), `store=false`, таймаут 20 с, без автоматических повторов. Имя, логин, пароль и чужая история не отправляются. Внешний OpenAI не является внутренним контуром: для закрытой сети оставьте ALLOW_EXTERNAL_AI=false. Флаг store=false не означает отсутствие всех служебных журналов провайдера.

## Прогресс, добровольность и приватность

Навык после выполнения = min(100, текущий + прирост активности). Готовность = 100 × сумма min(навык / цель, 1) × вес / сумма весов. XP отдельно: базовые баллы и целочисленный бонус 20% до дедлайна включительно. Дедлайн начинается при добровольном старте. Каждые 300 XP — новый личный уровень.

Опоздание не уменьшает баллы, отказ и пауза сохраняют прогресс. За обязательные процессы баллы не начисляются. Публичных рейтингов нет; личная история видна владельцу и HR. Сохранение в SQLite транзакционное. Выполнение пока является самоотчётом и не подтверждает реальную квалификацию или автоматическое повышение.

## Структура

```text
app.py                       # Вход, кабинет сотрудника и HR
run.py                       # Установка окружения и запуск одной командой
services/dataset.py          # Валидация формата
services/store.py            # SQLite, учётные записи, права, прогресс
services/recommendations.py  # Локальный подбор и OpenAI
data/demo.json               # Начальные вымышленные профили
data/jury-example.json       # Датасет для загрузки жюри
data/career_quest.sqlite3    # Создаётся при запуске, исключён из Git
tests/test_career_quest.py   # Проверки сервисов и интерфейса
.streamlit/config.toml      # Зелёная тема, параметры сервера
static/                     # Папки изображений, CSS, иконок
index.html                  # Статическая стартовая страница
Plan.md                     # Кейс, ограничения и критерии приёмки
```

## Проверки

В окружении с зависимостями: `python -m unittest discover -s tests -v`.
Тесты используют временную БД и подменённый OpenAI-клиент. Реальный API требует ключа и отдельной проверки. UI-сценарии проверяются через Streamlit AppTest.

Дальнейшие этапы: MySQL, корпоративный SSO, подтверждение результатов наставником, интеграция LMS/HRM. Речь и подсказки контакт-центра — отдельная итерация, не часть текущего карьерного MVP.
