# Career Quest — план проекта

## 1. Концепция

**Career Quest** — AI-навигатор развития сотрудника. Приложение связывает профиль сотрудника, историю HR-активностей и требования следующего грейда в понятный маршрут развития.

## 2. Проблема

Сотрудник сталкивается с потоком разрозненных HR-событий без видимой связи с развитием. Обучение проходит формально в день дедлайна, добровольные активности собирают низкую явку, а бюджет на развитие используется неэффективно.

## 3. Пользователи и стейкхолдеры

- Сотрудники со стажем 1–5 лет.
- HR-специалисты и руководители подразделений.
- Клиенты контакт-центра.
- Операторы и супервизоры.

## 4. Боли пользователей

- Как объяснить сотруднику, зачем нужна конкретная активность и к какому навыку она ведёт?
- Как сделать профессиональный рост видимым и мотивирующим?
- Как научить AI понимать клиента, говорящего живым языком?
- Как анализировать разговоры и давать подсказки без паузы дольше секунды?

## 5. Ценность продукта

Сотрудник получает персональный маршрут «следующий лучший шаг», объяснение пользы активности, карту навыков, XP и уровни за своевременное выполнение. HR и руководитель получают срез дефицитных компетенций и могут точнее направлять бюджет развития.

## 6. MVP-функциональность

### Кабинет сотрудника

- Профиль, текущий грейд и цель следующего грейда.
- Прогресс навыков и уровень Career Quest.
- AI-рекомендация следующего шага с обоснованием.
- Список активностей с дедлайнами, XP и статусами.
- Серия своевременных выполнений и бейджи.

### Кабинет HR / руководителя

- Средний прогресс команд.
- Рейтинг дефицитных компетенций.
- Участие в активностях и просрочки.
- Рекомендации по обучающим форматам и приоритетам бюджета.

### AI-слой

- Сопоставление профиля и истории сотрудника с требованиями грейда.
- Генерация краткого объяснения «почему это важно».
- Классификация намерения клиента и тональности обращения.
- Подсказка оператору в реальном времени с целевым временем ответа до 1 секунды.

## 7. Геймификация

- XP за выполнение активностей до дедлайна.
- Уровни: Новичок, Исследователь, Практик, Эксперт, Лидер.
- Бейджи: «Старт развития», «В ритме», «Без просрочек», «Мастер навыка».
- Прогресс-бар до следующего уровня.
- Серия своевременных выполнений (streak).

## 8. Технический план

- Frontend / MVP: Streamlit, HTML/CSS, адаптивная сетка.
- Backend: Python, слой сервисов для рекомендаций и прогресса.
- AI: OpenAI API через переменную `OPENAI_API_KEY`, с fallback на демо-данные.
- Хранилище MVP: SQLite с транзакциями; стартовый JSON-датасет. MySQL — следующий этап.
- Ассеты: `static/css`, `static/images`, `static/icons`.

## 9. Следующие итерации

1. Подключить корпоративный SSO/OIDC; в хакатон-демо использовать только синтетические профили.
2. Добавить MySQL-схему для сотрудников, навыков, активностей и событий.
3. Реализовать OpenAI-рекомендации и потоковую обработку транскрипта.
4. Добавить интеграции с LMS/HRM и журнал аудита рекомендаций.
5. Провести UX-тестирование на сотрудниках и операторах контакт-центра.

## 10. Must-have и приёмка текущей версии

| Требование | Проверка |
| --- | --- |
| Вход сотрудника и HR | Учётная запись определяет роль; сотрудник не открывает HR и чужой профиль, HR не выполняет шаги за сотрудника |
| Профиль и траектория | Открыть любой профиль в HR: роль, стаж, грейд, навыки, требования, история и доступные шаги |
| AI-рекомендация | OpenAI выбирает 1–3 подходящие активности; без настройки API явно показывается многофакторный локальный подбор |
| Объяснение | В каждом шаге видны четыре фактора: грейд, разрывы, требования следующего уровня, история; дополнительно предпочтение формата |
| Прогресс | Начать и завершить шаг: навык, готовность и XP меняются, сохраняются после перезапуска; повторное выполнение запрещено |
| HR-view | Частота дефицитов навыков, сотрудники без следующего шага с причиной, участие по активностям |
| Проверочные датасеты | HR загружает JSON-профили, требования, каталог и историю; валидация и атомарное добавление, выдача личных доступов |

### Контрольные примеры

1. Public Speaking ниже System Design, но история содержит три пропуска выступлений, а для следующего грейда критичен System Design. Приоритет — архитектурное менторство.
2. Низкий SQL не означает готовность к продвинутому курсу: проверяются предпосылки, история и формат. Рекомендован базовый практикум.
3. При отсутствии подходящих активностей система объясняет причину и показывает пробел каталога HR.

### Обязательные ограничения

- Только вымышленные данные, импорт требует подтверждения синтетического происхождения.
- Нет публичных рейтингов результативности; чужая вовлечённость не доступна сотруднику.
- Геймификация только добровольных активностей. Обязательные процессы исключены из подбора и начислений.
- Отказ и пауза не уменьшают XP и навыки; своевременное выполнение даёт бонус 20%, каждый уровень — 300 XP.
- Готовность считается по взвешенному покрытию требований, отдельно от XP; повышение грейда не автоматическое.
- По умолчанию локальный контур, внешний AI отключён. OpenAI включается конфигурацией и явным действием с согласием на передачу синтетических данных.
- Права проверяются в сервисном слое. Пароли хешируются, сессии отзываются при выходе. Публичные демо-доступы не подходят для реальных HR-данных.
- Запуск одной командой: `python run.py` при установленном Python 3.11+. Первое скачивание зависимостей требует интернета.

### Опционально, вне текущей реализации

Внутренняя валюта, каталог вознаграждений, признание коллег, командные вызовы, конструктор событий, моделирование грейда, календарь/мессенджер и казахская локализация. Менторство пока представлено форматом активности. Речь контакт-центра и подсказки с задержкой до секунды относятся к отдельному этапу, не к текущему карьерному MVP.
